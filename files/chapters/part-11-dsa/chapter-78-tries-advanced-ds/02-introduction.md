## Overview

Beyond basic data structures, several advanced structures solve specific problems extremely efficiently. Tries excel at string operations, segment trees handle range queries, and Fenwick trees provide elegant solutions for prefix-based operations.

### Junior → FAANG: The Three-Structure Mental Model

Entering this chapter with a clear mental model helps. Think of these structures as three specialized tools, each optimized for one access pattern. Tries are the tool for string-keyed lookups and prefix enumeration: if the problem mentions "prefix," "autocomplete," or "word search," a trie is the first thing to consider. Segment trees are the tool for interval-keyed aggregate queries with mutations: if the problem mentions "range sum/min/max with updates," a segment tree is the default. Fenwick trees are the lightweight version of segment trees, restricted to prefix-sum-style queries but with simpler code and better constants. Section 78.4 then adds a fourth tool that is different in kind: the LRU and LFU caches are not a single structure but a composition of two, a hash map for lookup and a linked list for ordering, each covering what the other cannot do alone. Structures whose dominant access pattern matches none of these, such as Union-Find for dynamic connectivity or monotonic stacks for next-greater-element scans, are covered in adjacent chapters.

### Senior @ FAANG: Advanced Structures as Competitive Moats and Technical Debt

At the senior level, advanced data structures represent a technical moat when used correctly and a technical debt risk when used unnecessarily. A trie in a high-traffic autocomplete service is a legitimate competitive advantage: it provides O(m) lookup regardless of vocabulary size, which is impossible with hash maps for prefix enumeration. But the same trie, implemented with a fixed 26-child array per node in a service handling Unicode user input, silently fails on non-ASCII characters and wastes memory at sparse vocabularies. The staff engineer's job is to evaluate not just "does this structure solve the problem?" but "is this the right structure given our constraints, and can the team maintain it safely?" When the answer is "yes but with caveats," those caveats go into the ADR: the Unicode handling model, the memory budget, the concurrency approach, and the upgrade path if the vocabulary grows beyond single-machine capacity.

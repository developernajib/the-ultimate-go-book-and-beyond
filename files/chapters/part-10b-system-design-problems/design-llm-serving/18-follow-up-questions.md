## Follow-up Questions

These questions test your understanding of emerging LLM serving challenges beyond the core inference pipeline.

**Q: Function calling?** Function calling (tool use) requires the LLM to generate structured output (a function name and arguments), execute the function externally, and feed the result back for continued generation. An orchestrator layer manages this loop between the API gateway and inference workers: it parses the model's output for function call tokens, routes the call to the appropriate tool endpoint with a 30-second timeout, and appends the tool result to the conversation context for the subsequent generation step. A maximum of 5 sequential tool calls per request prevents runaway loops. The key challenge is that each tool call adds a full round-trip (generation + external call + regeneration), so a 5-tool-call request may take 30+ seconds end-to-end.

**Q: Per-customer fine-tuned models?** LoRA (Low-Rank Adaptation) adapters add a small set of trainable parameters (well under 1% of the base model size) that customize the model's behavior for a specific customer or use case. At serving time, the adapter is loaded alongside the base model weights, swapping adapters takes approximately 10ms. This means 100 customers can share a single GPU cluster running the same base model, with per-request adapter loading. Adapters are stored in S3 (~100MB each for a 70B model) and cached on the GPU node's local NVMe SSD. The router selects the correct adapter based on the customer ID in the request, and the inference engine applies it during the forward pass.

**Q: Long contexts (128K+)?** Handling contexts beyond 128K tokens is constrained by GPU memory (KV cache grows linearly with context length) and computational cost (attention is quadratic in sequence length). Four strategies address this: (1) context windowing with summarization, where a smaller model compresses older parts of the context into summaries, (2) Retrieval-Augmented Generation (RAG) with a vector database, where only the most relevant chunks are included in the context rather than the full document, (3) KV cache offloading to NVMe SSD, which trades latency (loading cached pages from disk) for the ability to handle much longer contexts, and (4) ring attention across multiple GPUs, where the sequence is split across GPUs and each GPU computes attention over its local segment while communicating with neighbors.

**Q: Output quality at serving time?** Quality cannot be guaranteed by the model alone, production systems need additional guardrails. Input filters (under 50ms) check for prompt injection attacks, PII leakage requests, and policy-violating prompts. Output filters (under 50ms) scan generated text for policy violations, harmful content, and PII before sending to the client. A 1% random sample of responses is routed to human reviewers for quality assessment, creating a feedback loop for model improvement. New model versions are deployed via canary (5% of traffic for 30 minutes) with automated rollback if quality metrics (human evaluation scores, TTFT, error rates) degrade.

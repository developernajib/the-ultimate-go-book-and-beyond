# System Design: WhatsApp - Real-Time Messaging at Scale

> WhatsApp famously delivered on the order of 100 billion messages per day on an engineering team of a few dozen. That is infrastructure design as a competitive moat.

WhatsApp is the gold standard for engineering efficiency at scale. Delivering 100 billion messages per day to 2 billion users with a team of roughly 50 engineers means every architectural decision must minimize operational complexity while maximizing throughput. The system maintains 500 million concurrent WebSocket connections, each requiring persistent state on a connection server, and must deliver messages with sub-second latency even when sender and recipient are on different continents, where the speed of light alone costs you 150 to 250ms round trip.

The hardest engineering problems in this design are: (1) connection routing at scale, where 500 million persistent WebSocket connections must be distributed across 1,000+ servers with a fast lookup mechanism to route any message to the correct server in a single hop, (2) end-to-end encryption using the Signal Protocol, which means the server cannot read, index, or moderate message content, though it still sees the metadata of who talks to whom and when, and (3) offline message queuing with guaranteed delivery ordering, where the transport is at-least-once and the client deduplicates on a sender-assigned message ID to produce exactly-once *effects* in the correct sequence on reconnect.

This chapter implements each component in Go: a WebSocket connection server with Redis-backed presence routing, a Cassandra-backed chat service with per-conversation partitioning, group fan-out with configurable delivery strategies, pre-signed S3 media uploads, and the cryptographic building blocks of the Signal Protocol. You will learn why Cassandra is ideal for time-series message storage, how Redis Pub/Sub enables cross-server message routing, and how to design an offline queue that survives 30 days of disconnection.

The chapter begins with the problem statement and capacity estimation to establish the connection counts and message throughput that drive every design choice. The architecture overview lays out the major services, then core components provides Go implementations of the connection, chat, group, and media services. Database schema covers Cassandra and PostgreSQL table design, followed by a dedicated section on end-to-end encryption and the Signal Protocol. Key design decisions explains the major trade-offs, and the API design section defines the WebSocket and REST interfaces. Two deep dives explore the Signal Protocol's X3DH and Double Ratchet algorithms and push notifications with read receipts. The chapter continues with scaling strategy, failure handling, an interview scoring rubric, and common mistakes, then closes with follow-up questions, Redis data structure patterns, production Go implementations of the contact sync, status/stories, message backup, voice call signaling, message retention, and group call coordinator services, extended SQL schemas, multi-region deployment, data consistency models, a performance testing checklist, scale reference numbers, and extended scenarios including business features.

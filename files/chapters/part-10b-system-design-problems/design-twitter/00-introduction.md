# System Design: Twitter - Social Messaging Platform

> A tweet is a unit of thought. Your job is to deliver it to the right people in under 50ms.

Twitter is one of the most instructive system design problems because it forces you to solve the fan-out problem at massive scale. With 200 million daily active users generating 500 million tweets per day and 800 million timeline reads per day, the core challenge is distributing each tweet to the right set of followers with sub-100ms latency. The numbers define the problem: at 5,787 tweets per second average (17,000 at peak), each tweet must be pushed to an average of 200 followers, producing over 1 million Redis writes per second just for timeline fan-out.

The three hardest engineering problems in this design are: (1) the hybrid fan-out model, where celebrity accounts with millions of followers cannot use push-based distribution and must be handled with a pull-on-read strategy, (2) real-time trending detection, which requires distinguishing sudden spikes from permanently popular topics using statistical velocity scoring, and (3) full-text search across 500 million new tweets per day while keeping P99 query latency under 50ms.

This chapter walks through each component with production-quality Go implementations, covering Snowflake ID generation, Redis sorted set timelines, Elasticsearch hot/cold indexing, Kafka-based event distribution, and the scoring algorithms that power trending topics. By the end, you will understand how to design a system that handles billions of reads per day while keeping write amplification under control.

The chapter begins with learning objectives and a problem statement that frames the requirements, then moves into capacity estimation to establish the scale constraints that drive every subsequent decision. The high-level architecture section breaks down the major components before core components provides Go implementations of the key services. Database schema covers the data model, followed by key design decisions explaining the major trade-offs. The API design section defines the public interface, and three deep dives explore notification fan-out, rate limiting, and the follow graph in detail. The chapter continues with scaling strategy, failure handling, an interview scoring rubric, and common mistakes to avoid, then closes with follow-up questions, Redis data structure patterns, production Go implementations of the media upload, direct message, tweet hydration, and engagement counter services, extended SQL schemas, Kafka topic design, multi-region deployment, performance testing checklists, extended scenarios, and quick-reference scale and technology summaries.

## 90F.8 Complete: Go Linter + Code Generator for Real Use Case

### Use Case: HTTP Handler Authentication Enforcement

A common problem in large Go services: HTTP handlers get added without authentication middleware. We'll build:
1. A linter that detects unprotected handlers
2. A code generator that produces the auth middleware wrapper

```go
// linter/authrequired/analyzer.go
package authrequired

import (
    "go/ast"
    "go/types"
    "strings"

    "golang.org/x/tools/go/analysis"
    "golang.org/x/tools/go/analysis/passes/inspect"
    "golang.org/x/tools/go/ast/inspector"
)

var Analyzer = &analysis.Analyzer{
    Name:     "authrequired",
    Doc:      "Find HTTP handlers registered without authentication middleware",
    Requires: []*analysis.Analyzer{inspect.Analyzer},
    Run:      run,
}

// authWrappedFunctions tracks which functions are known auth wrappers
var knownAuthWrappers = map[string]bool{
    "RequireAuth":    true,
    "RequireAdmin":   true,
    "RequireRole":    true,
    "AuthMiddleware": true,
}

func run(pass *analysis.Pass) (any, error) {
    insp := pass.ResultOf[inspect.Analyzer].(*inspector.Inspector)

    insp.Preorder([]ast.Node{(*ast.CallExpr)(nil)}, func(n ast.Node) {
        call := n.(*ast.CallExpr)

        // Look for http.HandleFunc or router.GET/POST/etc.
        if !isRouteRegistration(pass, call) {
            return
        }

        // Get the handler argument
        handlerArg := getHandlerArg(call)
        if handlerArg == nil {
            return
        }

        // Check if handler is wrapped in auth middleware
        if !isWrappedInAuth(pass, handlerArg) {
            pass.Reportf(
                call.Pos(),
                "HTTP handler registered without authentication middleware; wrap with RequireAuth() or similar",
            )
        }
    })

    return nil, nil
}

func isRouteRegistration(pass *analysis.Pass, call *ast.CallExpr) bool {
    sel, ok := call.Fun.(*ast.SelectorExpr)
    if !ok {
        return false
    }

    obj := pass.TypesInfo.Uses[sel.Sel]
    if obj == nil {
        return false
    }

    fn, ok := obj.(*types.Func)
    if !ok {
        return false
    }

    // Check for http.HandleFunc
    if fn.Pkg() != nil && fn.Pkg().Path() == "net/http" && fn.Name() == "HandleFunc" {
        return true
    }

    // Check for chi/echo router methods
    if fn.Name() == "GET" || fn.Name() == "POST" || fn.Name() == "PUT" ||
        fn.Name() == "DELETE" || fn.Name() == "PATCH" {
        return true
    }

    return false
}

func getHandlerArg(call *ast.CallExpr) ast.Expr {
    switch len(call.Args) {
    case 1:
        return call.Args[0] // Router method with just handler
    case 2:
        return call.Args[1] // http.HandleFunc(pattern, handler)
    }
    return nil
}

func isWrappedInAuth(pass *analysis.Pass, expr ast.Expr) bool {
    callExpr, ok := expr.(*ast.CallExpr)
    if !ok {
        return false
    }

    // Get the function being called
    var funcName string
    switch fn := callExpr.Fun.(type) {
    case *ast.Ident:
        funcName = fn.Name
    case *ast.SelectorExpr:
        funcName = fn.Sel.Name
    }

    if knownAuthWrappers[funcName] {
        return true
    }

    // Check if it's a method that contains "Auth" in the name
    return strings.Contains(strings.ToLower(funcName), "auth") ||
        strings.Contains(strings.ToLower(funcName), "require")
}
```

### The Code Generator Companion

The linter detects the problem, but a code generator accelerates the fix by automatically producing auth-wrapped route registrations. This generator reads the existing `routes.go` file using `go/ast`, extracts every `HandleFunc` call along with its URL pattern and handler name, and emits a new file that wraps each handler with authentication middleware. Pairing a linter with a generator creates a complete workflow: the linter blocks unprotected routes from being merged, while the generator makes it trivial to produce the correct code in the first place.

```go
// cmd/authgen/main.go - generates auth-wrapped route registration boilerplate
package main

import (
    "flag"
    "fmt"
    "go/ast"
    "go/importer"
    "go/parser"
    "go/token"
    "go/types"
    "os"
    "strings"
    "text/template"
)

// RouteInfo represents an HTTP route found in the source
type RouteInfo struct {
    Method      string
    Pattern     string
    HandlerName string
    NeedsAuth   bool
}

const wrappedRouteTemplate = `// Code generated by authgen. DO NOT EDIT.
// Run: go generate ./...
package {{.Package}}

import "net/http"

// RegisterRoutesWithAuth registers all routes with authentication middleware applied.
// Generated from routes found in routes.go
func RegisterRoutesWithAuth(mux *http.ServeMux, auth func(http.HandlerFunc) http.HandlerFunc) {
{{range .Routes}}    mux.HandleFunc("{{.Pattern}}", {{if .NeedsAuth}}auth({{.HandlerName}}){{else}}{{.HandlerName}}{{end}})
{{end}}}
`

func main() {
    inputFile := flag.String("input", "routes.go", "input file to analyze")
    outputFile := flag.String("output", "routes_auth_gen.go", "output file")
    flag.Parse()

    routes, pkg, err := extractRoutes(*inputFile)
    if err != nil {
        fmt.Fprintf(os.Stderr, "error: %v\n", err)
        os.Exit(1)
    }

    tmpl, err := template.New("routes").Parse(wrappedRouteTemplate)
    if err != nil {
        fmt.Fprintf(os.Stderr, "parsing template: %v\n", err)
        os.Exit(1)
    }

    f, err := os.Create(*outputFile)
    if err != nil {
        fmt.Fprintf(os.Stderr, "creating output: %v\n", err)
        os.Exit(1)
    }
    defer f.Close()

    tmpl.Execute(f, struct {
        Package string
        Routes  []RouteInfo
    }{Package: pkg, Routes: routes})

    fmt.Printf("Generated %s with %d routes\n", *outputFile, len(routes))
}

func extractRoutes(filename string) ([]RouteInfo, string, error) {
    fset := token.NewFileSet()
    f, err := parser.ParseFile(fset, filename, nil, parser.ParseComments)
    if err != nil {
        return nil, "", err
    }

    conf := types.Config{Importer: importer.Default()}
    info := &types.Info{
        Uses: make(map[*ast.Ident]types.Object),
    }
    pkg, err := conf.Check(f.Name.Name, fset, []*ast.File{f}, info)
    if err != nil {
        return nil, "", err
    }

    var routes []RouteInfo
    ast.Inspect(f, func(n ast.Node) bool {
        call, ok := n.(*ast.CallExpr)
        if !ok {
            return true
        }

        // Look for mux.HandleFunc or similar
        sel, ok := call.Fun.(*ast.SelectorExpr)
        if !ok || sel.Sel.Name != "HandleFunc" {
            return true
        }

        if len(call.Args) < 2 {
            return true
        }

        patternLit, ok := call.Args[0].(*ast.BasicLit)
        if !ok {
            return true
        }

        handlerIdent, ok := call.Args[1].(*ast.Ident)
        if !ok {
            return true
        }

        pattern := strings.Trim(patternLit.Value, `"`)

        // Check if handler has @auth comment
        needsAuth := false
        for _, cg := range f.Comments {
            for _, c := range cg.List {
                if strings.Contains(c.Text, "@auth") {
                    needsAuth = true
                }
            }
        }

        routes = append(routes, RouteInfo{
            Pattern:     pattern,
            HandlerName: handlerIdent.Name,
            NeedsAuth:   needsAuth,
        })

        _ = pkg
        return true
    })

    return routes, f.Name.Name, nil
}
```

### Senior @ FAANG: Combined Tooling as a Security Control

At L6, the linter-generator combination is a security control, not just a productivity tool. The linter prevents unprotected routes from existing in production (security guarantee). The generator makes it trivially easy to produce protected routes (removes friction from the correct path). Together they implement the principle that the correct behavior should be the easy behavior. This is exactly the kind of security-by-default thinking that bar-raiser interviewers at security-conscious FAANG companies probe for.

At staff level, this system also raises governance questions: who reviews changes to the auth wrapper generated by the generator? What is the test coverage for the linter's false-negative rate (cases where a handler is genuinely unprotected but the linter misses it)? How is the linter updated when new router libraries are adopted? These questions belong in the design doc alongside the implementation, and answering them is part of what makes this a staff-level contribution rather than an L5 one.

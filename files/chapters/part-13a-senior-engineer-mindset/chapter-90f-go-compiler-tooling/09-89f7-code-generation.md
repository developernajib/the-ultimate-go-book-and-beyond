## 90F.7 Code Generation

### go generate Workflow

The `//go:generate` directive embeds shell commands directly into Go source files, which `go generate ./...` executes as a preprocessing step before compilation. This mechanism is how the Go ecosystem handles code that must be derived from other definitions: `stringer` generates `String()` methods from `iota` enumerations, `mockgen` generates test doubles from interfaces, and `protoc` generates gRPC client/server stubs from `.proto` files. Placing the directive next to the type it affects keeps the generation command discoverable and version-controlled alongside the source.

```go
// go:generate directive - runs commands when `go generate ./...` is called

// stringer - generate String() method for enum types
//go:generate go run golang.org/x/tools/cmd/stringer -type=Status

type Status int

const (
    StatusPending Status = iota
    StatusActive
    StatusInactive
    StatusDeleted
)

// After running go generate:
// status_string.go is created with:
// func (i Status) String() string { ... }

// mockgen - generate mock implementations
//go:generate go run github.com/golang/mock/mockgen -source=service.go -destination=mock_service.go

type User struct{}
type CreateUserRequest struct{}

type UserService interface {
    GetUser(ctx context.Context, id string) (*User, error)
    CreateUser(ctx context.Context, req CreateUserRequest) (*User, error)
}

// Generates MockUserService implementing UserService
```

### Template-Based Code Generation

When a standard generator tool does not exist for your pattern, writing a custom generator using `text/template` is the appropriate approach. The repository pattern is a good candidate for generation: the CRUD methods are structurally identical across entity types, differing only in type name, table name, and field list. The generator below reads a `RepoConfig` struct and emits a fully-formed repository implementation, eliminating copy-paste drift across entity repositories and ensuring every generated file contains the `// Code generated ... DO NOT EDIT.` marker.

```go
// codegen/generate.go - code generator for repository pattern
package main

import (
    "fmt"
    "os"
    "strings"
    "text/template"
)

type RepoConfig struct {
    Package    string
    EntityName string
    TableName  string
    PrimaryKey string
    Fields     []Field
}

type Field struct {
    Name       string
    Type       string
    DBColumn   string
    PrimaryKey bool
}

const repoTemplate = `// Code generated by repogen. DO NOT EDIT.
package {{.Package}}

import (
    "context"
    "database/sql"
    "fmt"
)

// {{.EntityName}}Repository provides CRUD operations for {{.EntityName}}.
type {{.EntityName}}Repository struct {
    db *sql.DB
}

func New{{.EntityName}}Repository(db *sql.DB) *{{.EntityName}}Repository {
    return &{{.EntityName}}Repository{db: db}
}

func (r *{{.EntityName}}Repository) GetByID(ctx context.Context, id string) (*{{.EntityName}}, error) {
    var entity {{.EntityName}}
    err := r.db.QueryRowContext(ctx,
        "SELECT {{range $i, $f := .Fields}}{{if $i}}, {{end}}{{$f.DBColumn}}{{end}} FROM {{.TableName}} WHERE {{.PrimaryKey}} = $1",
        id,
    ).Scan({{range $i, $f := .Fields}}{{if $i}}, {{end}}&entity.{{$f.Name}}{{end}})
    if err == sql.ErrNoRows {
        return nil, nil
    }
    if err != nil {
        return nil, fmt.Errorf("getting {{.EntityName}} by id: %w", err)
    }
    return &entity, nil
}

func (r *{{.EntityName}}Repository) Create(ctx context.Context, entity *{{.EntityName}}) error {
    _, err := r.db.ExecContext(ctx,
        "INSERT INTO {{.TableName}} ({{range $i, $f := .Fields}}{{if $i}}, {{end}}{{$f.DBColumn}}{{end}}) VALUES ({{range $i, $f := .Fields}}{{if $i}}, {{end}}${{add $i 1}}{{end}})",
        {{range $i, $f := .Fields}}{{if $i}}, {{end}}entity.{{$f.Name}}{{end}},
    )
    if err != nil {
        return fmt.Errorf("creating {{.EntityName}}: %w", err)
    }
    return nil
}
`

func generateRepo(config RepoConfig, outputFile string) error {
    funcMap := template.FuncMap{
        "add": func(a, b int) int { return a + b },
        "lower": strings.ToLower,
    }

    tmpl, err := template.New("repo").Funcs(funcMap).Parse(repoTemplate)
    if err != nil {
        return fmt.Errorf("parsing template: %w", err)
    }

    f, err := os.Create(outputFile)
    if err != nil {
        return fmt.Errorf("creating output file: %w", err)
    }
    defer f.Close()

    return tmpl.Execute(f, config)
}

func main() {
    config := RepoConfig{
        Package:    "repo",
        EntityName: "User",
        TableName:  "users",
        PrimaryKey: "id",
        Fields: []Field{
            {Name: "ID", Type: "string", DBColumn: "id", PrimaryKey: true},
            {Name: "Email", Type: "string", DBColumn: "email"},
            {Name: "Name", Type: "string", DBColumn: "name"},
            {Name: "CreatedAt", Type: "time.Time", DBColumn: "created_at"},
        },
    }

    if err := generateRepo(config, "user_repository_gen.go"); err != nil {
        panic(err)
    }
    fmt.Println("Generated user_repository_gen.go")
}
```

### Writing a Custom protoc Plugin

Protocol Buffer plugins are programs that read a `CodeGeneratorRequest` from stdin and write a `CodeGeneratorResponse` to stdout.

```go
// cmd/protoc-gen-goauth/main.go
// Generates authentication middleware for gRPC services
// protoc --goauth_out=. --goauth_opt=paths=source_relative service.proto

package main

import (
    "fmt"
    "strings"
    "text/template"

    "google.golang.org/protobuf/compiler/protogen"
    "google.golang.org/protobuf/types/pluginpb"
)

// AuthOption is a custom file option we look for in .proto files
// Defined in our own options.proto:
// extend google.protobuf.MethodOptions {
//   bool require_auth = 50000;
// }

const authMiddlewareTemplate = `// Code generated by protoc-gen-goauth. DO NOT EDIT.
package {{.Package}}

import (
    "context"
    "google.golang.org/grpc"
    "google.golang.org/grpc/codes"
    "google.golang.org/grpc/status"
    "github.com/yourcompany/auth"
)

// {{.ServiceName}}AuthInterceptor returns a gRPC UnaryServerInterceptor
// that enforces authentication for methods marked with require_auth = true.
func {{.ServiceName}}AuthInterceptor(authSvc auth.Service) grpc.UnaryServerInterceptor {
    return func(ctx context.Context, req any, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (any, error) {
        switch info.FullMethod {
{{range .AuthMethods}}        case "{{.FullPath}}":
            if err := authSvc.ValidateRequest(ctx); err != nil {
                return nil, status.Errorf(codes.Unauthenticated, "authentication required: %v", err)
            }
{{end}}        }
        return handler(ctx, req)
    }
}
`

type AuthTemplateData struct {
    Package     string
    ServiceName string
    AuthMethods []AuthMethod
}

type AuthMethod struct {
    Name     string
    FullPath string
}

func main() {
    protogen.Options{
        ParamFunc: func(name, value string) error { return nil },
    }.Run(func(gen *protogen.Plugin) error {
        gen.SupportedFeatures = uint64(pluginpb.CodeGeneratorResponse_FEATURE_PROTO3_OPTIONAL)

        for _, f := range gen.Files {
            if !f.Generate {
                continue
            }
            generateAuth(gen, f)
        }
        return nil
    })
}

func generateAuth(gen *protogen.Plugin, f *protogen.File) {
    for _, svc := range f.Services {
        data := AuthTemplateData{
            Package:     string(f.GoPackageName),
            ServiceName: svc.GoName,
        }

        for _, m := range svc.Methods {
            // Check for require_auth option (simplified - real impl reads proto option)
            if strings.Contains(string(m.Comments.Leading), "@require_auth") {
                data.AuthMethods = append(data.AuthMethods, AuthMethod{
                    Name:     string(m.GoName),
                    FullPath: fmt.Sprintf("/%s/%s", svc.Desc.FullName(), m.Desc.Name()),
                })
            }
        }

        if len(data.AuthMethods) == 0 {
            continue
        }

        filename := f.GeneratedFilenamePrefix + "_auth.pb.go"
        g := gen.NewGeneratedFile(filename, f.GoImportPath)

        tmpl, _ := template.New("auth").Parse(authMiddlewareTemplate)
        var buf strings.Builder
        tmpl.Execute(&buf, data)
        g.P(buf.String())
    }
}

// Build and use:
// go build -o protoc-gen-goauth ./cmd/protoc-gen-goauth
// PATH=$PATH:. protoc --goauth_out=. service.proto
```

### Junior → FAANG: Code Generation as a Productivity Signal

Mentioning that you have written a `go generate` code generator in an interview signals that you think about developer productivity, not just feature delivery. You do not need to have written a protoc plugin. A template-based repository generator or a type-safe mock generator is enough. The key interview framing is: "I identified a pattern we were repeating manually across services, turned it into a generator, and saved the team N hours per quarter." That is impact language that FAANG interviewers respond to.

### Senior @ FAANG: Code Generation as Infrastructure Investment

At L6, the question is not whether to use code generation but how to make generated code maintainable at scale. The invariants are: generated files are never edited manually (enforced by the `DO NOT EDIT` header and a CI check that regenerates and diffs), the generator is tested with golden files (so regressions are caught immediately), and the generator is documented with enough clarity that an engineer unfamiliar with protoc internals can understand what it produces and why. Without these invariants, generated code becomes a maintenance liability rather than an asset.

The protoc plugin pattern is significant at staff level because it is a platform decision: you are defining the canonical way that gRPC services in your org enforce authentication. Every service that uses the plugin benefits from the same enforcement, and changes to the auth policy propagate through a single regeneration rather than manual updates across hundreds of files. This is organizational leverage at its most concrete.

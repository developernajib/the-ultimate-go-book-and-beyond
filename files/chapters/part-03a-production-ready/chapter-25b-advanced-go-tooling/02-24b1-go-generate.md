## 25B.1 go generate

### What go generate Does

`go generate` is a Go tool that reads `//go:generate` directives in `.go` files and runs arbitrary commands. It does not run automatically - you invoke it explicitly with `go generate ./...`.

```go
// file: status.go
package model

//go:generate stringer -type=Status -output=status_string.go
//go:generate go run ./gen/gen_validators.go -type=Status

// Status represents the state of a job
type Status int

const (
    StatusPending Status = iota
    StatusRunning
    StatusCompleted
    StatusFailed
    StatusCanceled
)
```

Once the directives are in place, you run `go generate` from the command line. It scans `.go` files for `//go:generate` comments and executes each command in order.

```bash
# Running generators
go generate ./...           # run all generators in the project
go generate ./model/...     # run generators in a subtree
go generate -v ./...        # verbose: show each command before running
go generate -n ./...        # dry run: print commands without running

# Output of go generate for the above:
# stringer -type=Status -output=status_string.go
# go run ./gen/gen_validators.go -type=Status
```

### stringer: Auto-Generate String() Methods for Enums

Go's `iota`-based enums are just integers at runtime, so without a `String()` method they print as bare numbers in logs and error messages. The `stringer` tool from `golang.org/x/tools` inspects your type definition and generates an efficient, bounds-checked `String()` implementation that maps each constant to its source name using a compact index into a single concatenated string, no `map` allocation required.

```bash
# Install
go install golang.org/x/tools/cmd/stringer@latest

# Usage:
stringer -type=Status -output=status_string.go
```

```go
// Generated file: status_string.go (do not edit manually)
// This file was generated by stringer - DO NOT EDIT.

package model

import "strconv"

func _() {
    // An "invalid array index" compiler error signifies that the constant values
    // have changed. Re-run the stringer command to generate them again.
    var x [1]struct{}
    _ = x[StatusPending-0]
    _ = x[StatusRunning-1]
    _ = x[StatusCompleted-2]
    _ = x[StatusFailed-3]
    _ = x[StatusCanceled-4]
}

const _Status_name = "PendingRunningCompletedFailedCanceled"
var _Status_index = [...]uint8{0, 7, 14, 23, 29, 37}

func (i Status) String() string {
    if i < 0 || i >= Status(len(_Status_index)-1) {
        return "Status(" + strconv.FormatInt(int64(i), 10) + ")"
    }
    return _Status_name[_Status_index[i]:_Status_index[i+1]]
}
```

### mockgen: Auto-Generate Mock Implementations

Hand-writing mock implementations for every interface is tedious and error-prone when interfaces change. `mockgen` from `go.uber.org/mock` reads either a source file or a compiled package and generates a full mock struct whose method expectations and return values you can configure per test, giving you compile-time safety and expressive `EXPECT()` assertions without any boilerplate.

```bash
# Install
go install go.uber.org/mock/mockgen@latest

# Source mode: generate mocks for interfaces in a specific file
mockgen -source=service.go -destination=mocks/service_mock.go -package=mocks

# Reflect mode: generate mocks for specific types
mockgen -destination=mocks/db_mock.go -package=mocks \
    github.com/myorg/myapp/db DBInterface
```

The typical workflow embeds the `//go:generate` directive directly in the source file that declares the interface, so regenerating the mock is a single `go generate ./...` away.

```go
// file: service.go
package service

//go:generate mockgen -source=service.go -destination=mocks/service_mock.go -package=mocks

// UserRepository defines the data access interface
type UserRepository interface {
    GetByID(id int64) (*User, error)
    Create(user *User) error
    Update(user *User) error
    Delete(id int64) error
    List(limit, offset int) ([]*User, error)
}

type User struct {
    ID    int64
    Name  string
    Email string
}
```

With the mock generated, tests create a `gomock.Controller`, build the mock, and set expectations on specific method calls. The mock fails the test automatically if an unexpected call occurs or an expected call is missing.

```go
// file: service_test.go - using the generated mock
package service_test

import (
    "testing"
    "go.uber.org/mock/gomock"
    "myapp/mocks"
)

func TestGetUser(t *testing.T) {
    ctrl := gomock.NewController(t)
    defer ctrl.Finish()

    // Create mock from generated code
    mockRepo := mocks.NewMockUserRepository(ctrl)

    // Set expectations
    mockRepo.EXPECT().
        GetByID(int64(1)).
        Return(&User{ID: 1, Name: "Alice"}, nil).
        Times(1)

    // Test the service with the mock
    svc := NewUserService(mockRepo)
    user, err := svc.GetUser(1)

    if err != nil || user.Name != "Alice" {
        t.Fatalf("unexpected result: %v %v", user, err)
    }
}
```

### sqlc: Generate Type-Safe Go from SQL

Writing raw SQL in Go typically requires casting query results through `interface{}` and scattering `row.Scan` calls throughout your codebase, a maintenance burden that silently breaks when the schema changes. `sqlc` reads your SQL schema and query files and generates fully type-safe Go functions and structs that match every column exactly, turning schema drift into a compile error rather than a runtime panic.

```bash
# Install
go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest

# Generate
sqlc generate
```

Configuration lives in `sqlc.yaml` at the project root. It specifies the SQL engine, the directories containing schema and query files, and the Go package where generated code should land.

```yaml
# file: sqlc.yaml
version: "2"
sql:
  - engine: "postgresql"
    queries: "queries/"
    schema: "schema/"
    gen:
      go:
        package: "db"
        out: "internal/db"
        emit_json_tags: true
        emit_prepared_queries: true
        emit_interface: true
```

Query files use special comment annotations (`-- name: FuncName :one`, `:many`, `:exec`) to tell sqlc what Go function signature to generate for each SQL statement.

```sql
-- file: queries/users.sql
-- name: GetUser :one
SELECT * FROM users WHERE id = $1 LIMIT 1;

-- name: ListUsers :many
SELECT * FROM users ORDER BY name LIMIT $1 OFFSET $2;

-- name: CreateUser :one
INSERT INTO users (name, email) VALUES ($1, $2) RETURNING *;

-- name: UpdateUser :one
UPDATE users SET name = $2, email = $3 WHERE id = $1 RETURNING *;

-- name: DeleteUser :exec
DELETE FROM users WHERE id = $1;
```

Running `sqlc generate` produces Go functions that match each annotated query. Every parameter and return column is mapped to a concrete Go type, so a schema change that removes a column becomes a compile error in every caller.

```go
// Generated file: internal/db/users.sql.go (do not edit)
package db

import "context"

// GetUser retrieves a user by ID (type-safe, no interface{}, no runtime errors)
func (q *Queries) GetUser(ctx context.Context, id int64) (User, error) {
    row := q.db.QueryRowContext(ctx, getUserQuery, id)
    var i User
    err := row.Scan(&i.ID, &i.Name, &i.Email, &i.CreatedAt, &i.UpdatedAt)
    return i, err
}

const getUserQuery = `-- name: GetUser :one
SELECT id, name, email, created_at, updated_at FROM users WHERE id = $1 LIMIT 1`
```

### Writing a Custom Code Generator

When existing tools don't cover your domain, say, you need to generate a Builder pattern for every config struct in your package, you can write a generator that uses Go's `go/parser` and `go/ast` packages to inspect source code and `text/template` to emit new Go files. The generator below walks the AST of the current directory, extracts exported fields from the named struct, and writes a fluent Builder that `go/format` normalizes to standard style before writing to disk.

Three details in it are the difference between a generator that works and one that emits confident garbage, and all three are easy to get wrong.

**Render types with `types.ExprString`, not a hand-rolled switch.** A type in the AST is an arbitrary expression, and a switch over `*ast.Ident`, `*ast.StarExpr`, `*ast.ArrayType`, and `*ast.SelectorExpr` covers only the easy cases. Fall through to a `default` that prints `%T` and a `map[string]string` field silently becomes the literal text `*ast.MapType` in your output. `go/types.ExprString` renders any type expression correctly, including maps, channels, function types, and generics.

**Emit the imports.** Templating `package foo` and jumping straight to the code produces a file that cannot compile the moment a field's type is qualified: a single `time.Duration` field yields `undefined: time`. The generator has to notice which packages the selected fields reference and carry those imports through. (An alternative is to run the output through `golang.org/x/tools/imports.Process`, which resolves imports the way `goimports` does, at the cost of a dependency.)

**Check the errors you are tempted to drop.** `tmpl.Execute` and `os.WriteFile` both return errors, and ignoring them gives you a generator that prints `Generated config_builder.go` and exits 0 having written nothing, or having written a truncated file. A generator that lies about success is worse than one that crashes.

One note on `parser.ParseDir`: it is not deprecated, but it does not consider build tags when associating files with packages, so a directory with platform-specific files can give it a view that does not match any real build. It is fine for a single-purpose generator on a directory you control, which is why it is used here, and `golang.org/x/tools/go/packages` is the right answer when you need type information or build-tag awareness.

```go
// file: gen/gen_builder.go
// This generator reads a struct and generates a Builder pattern for it.
// Run with: go run ./gen/gen_builder.go -type=Config -pkg=config

package main

import (
	"bytes"
	"flag"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"go/types"
	"os"
	"sort"
	"strings"
	"text/template"
	"unicode"
)

var (
	typeName = flag.String("type", "", "struct type to generate builder for")
	pkgName  = flag.String("pkg", "", "package name")
	outFile  = flag.String("out", "", "output file (default: <type>_builder.go)")
)

type FieldInfo struct {
	Name string
	Type string
}

type BuilderData struct {
	Package string
	Type    string
	Imports []string
	Fields  []FieldInfo
}

const builderTemplate = `// Code generated by gen_builder. DO NOT EDIT.

package {{.Package}}
{{if .Imports}}
import (
{{range .Imports}}	{{.}}
{{end}})
{{end}}
// {{.Type}}Builder provides a fluent API for constructing {{.Type}} instances.
type {{.Type}}Builder struct {
	v {{.Type}}
}

// New{{.Type}}Builder creates a new builder with zero values.
func New{{.Type}}Builder() *{{.Type}}Builder {
	return &{{.Type}}Builder{}
}

{{range .Fields}}
// Set{{.Name}} sets the {{.Name}} field.
func (b *{{$.Type}}Builder) Set{{.Name}}(v {{.Type}}) *{{$.Type}}Builder {
	b.v.{{.Name}} = v
	return b
}
{{end}}
// Build returns the constructed {{.Type}}.
func (b *{{.Type}}Builder) Build() {{.Type}} {
	return b.v
}
`

func main() {
	flag.Parse()
	if *typeName == "" || *pkgName == "" {
		flag.Usage()
		os.Exit(1)
	}

	fset := token.NewFileSet()
	pkgs, err := parser.ParseDir(fset, ".", nil, 0)
	if err != nil {
		fatalf("parse error: %v", err)
	}

	var fields []FieldInfo
	usedPkgs := map[string]bool{}
	fileImports := map[string]string{}

	for _, pkg := range pkgs {
		for _, file := range pkg.Files {
			for _, imp := range file.Imports {
				path := strings.Trim(imp.Path.Value, `"`)
				name := path[strings.LastIndex(path, "/")+1:]
				if imp.Name != nil {
					name = imp.Name.Name
				}
				fileImports[name] = imp.Path.Value
			}
			ast.Inspect(file, func(n ast.Node) bool {
				ts, ok := n.(*ast.TypeSpec)
				if !ok || ts.Name.Name != *typeName {
					return true
				}
				st, ok := ts.Type.(*ast.StructType)
				if !ok {
					return false
				}
				for _, field := range st.Fields.List {
					if len(field.Names) == 0 {
						continue
					}
					name := field.Names[0].Name
					if !unicode.IsUpper(rune(name[0])) {
						continue
					}
					fields = append(fields, FieldInfo{
						Name: name,
						Type: types.ExprString(field.Type),
					})
					collectPkgs(field.Type, usedPkgs)
				}
				return false
			})
		}
	}

	if len(fields) == 0 {
		fatalf("type %q not found or has no exported fields", *typeName)
	}

	var imports []string
	for name := range usedPkgs {
		if path, ok := fileImports[name]; ok {
			imports = append(imports, path)
		}
	}
	sort.Strings(imports)

	tmpl, err := template.New("builder").Parse(builderTemplate)
	if err != nil {
		fatalf("template error: %v", err)
	}

	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, BuilderData{
		Package: *pkgName, Type: *typeName, Imports: imports, Fields: fields,
	}); err != nil {
		fatalf("execute error: %v", err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		fatalf("format error: %v\n%s", err, buf.String())
	}

	out := *outFile
	if out == "" {
		out = strings.ToLower(*typeName) + "_builder.go"
	}
	if err := os.WriteFile(out, formatted, 0o644); err != nil {
		fatalf("writing %s: %v", out, err)
	}
	fmt.Printf("Generated %s\n", out)
}

func collectPkgs(expr ast.Expr, out map[string]bool) {
	ast.Inspect(expr, func(n ast.Node) bool {
		if sel, ok := n.(*ast.SelectorExpr); ok {
			if id, ok := sel.X.(*ast.Ident); ok {
				out[id.Name] = true
			}
		}
		return true
	})
}

func fatalf(format string, args ...any) {
	fmt.Fprintf(os.Stderr, format+"\n", args...)
	os.Exit(1)
}
```

### Staff Lens: Custom Generators When Standard Ones Do Not Fit

Stringer, mockgen, sqlc cover 80% of generation needs. For the remaining 20%, a custom generator is justified. But verify the need: often the hand-written code is simpler than a custom generator, and the generator itself becomes a maintenance burden.

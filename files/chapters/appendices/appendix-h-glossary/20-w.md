## W

### WaitGroup (`sync.WaitGroup`)
A fundamental Go synchronization primitive used to wait for a collection of concurrent goroutines to finish execution. A `sync.WaitGroup` maintains an internal counter incremented with `Add()`, decremented with `Done()`, and blocked upon with `Wait()`. `Add()` must always be called before launching the goroutine to prevent race conditions.

```go
var wg sync.WaitGroup
for _, job := range jobs {
    wg.Add(1)
    go func(j Job) {
        defer wg.Done()
        process(j)
    }(job)
}
wg.Wait()
```

### Write-Ahead Logging (WAL)
A durability pattern in storage engines and databases where data mutations are appended sequentially to a durable on-disk log file before being applied to in-memory tables or index trees. If a node crashes, the database replays the WAL to recover uncommitted transactions without data loss.

### Write Barrier
A compiler-generated hook injected before memory pointer writes during active garbage collection phases. In Go's concurrent tri-color mark-and-sweep collector, the hybrid write barrier ensures that the garbage collector does not accidentally overlook newly allocated or rearranged pointers while the user application continues to run concurrently.

### Worker Pool
A concurrency design pattern where a fixed number of long-running worker goroutines pull tasks from a shared channel queue. Worker pools limit concurrency, preventing runaway memory exhaustion and downstream service throttling under burst traffic.

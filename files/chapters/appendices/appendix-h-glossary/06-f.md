## F

### Fallthrough
A Go keyword used exclusively inside a `switch` statement case block to force execution into the body of the immediately following `case`, bypassing that case's condition check. In Go, cases break automatically by default; `fallthrough` must be explicitly declared and cannot be used in the final case of a switch.

```go
switch tier {
case "enterprise":
    enableSLA()
    fallthrough
case "standard":
    enableBasicAccess()
}
```

### Fan-In / Fan-Out
A foundational Go concurrency design pattern. **Fan-Out** describes starting multiple goroutines to handle tasks from a single input channel concurrently, multiplying throughput. **Fan-In** describes multiplexing the outputs of multiple concurrent worker channels back into a single unified destination channel using a coordinating goroutine or `sync.WaitGroup`.

### Fast Path
An optimization technique where an algorithm quickly handles the most common, contention-free case with minimal CPU instructions (e.g., an atomic CAS check), falling back to a slower, more complex "slow path" (e.g., acquiring an OS mutex or allocating heap memory) only when necessary. Go's `sync.Mutex` and `sync.Once` utilize fast paths.

### Finalizer
A function registered via `runtime.SetFinalizer()` that the Go runtime invokes when an object is deemed unreachable by the garbage collector before its memory is freed. Finalizers are generally discouraged in production Go because their execution timing is non-deterministic and can delay memory reclamation.

### Flame Graph
A hierarchical visualization of profiled software software execution developed by Brendan Gregg. In Go, flame graphs generated from `go tool pprof` display function call stacks along the vertical axis and CPU time or memory allocations along the horizontal axis, making hot execution paths immediately apparent.

### Floating-Point Precision
Standard IEEE 754 representations of real numbers (`float32` and `float64` in Go). Engineers must never use floating-point numbers for currency or financial calculations due to representation rounding errors; use integers (cents) or arbitrary-precision libraries like `math/big`.

### Fork-Exec
The standard Unix process creation mechanism where `fork()` duplicates the calling process, followed by `execve()` replacing the process image with a new executable. In Go, process spawning is handled safely via `os/exec.Command`, which coordinates with the Go runtime to prevent thread corruption.

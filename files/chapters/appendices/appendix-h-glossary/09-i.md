## I

### Interface
An abstract type defined as a set of method signatures. In Go, interfaces are implemented **implicitly** without an `implements` keyword. An interface value is represented internally as a two-word pair: `(type_descriptor, data_pointer)`.

### Idempotency
An algorithmic or API property where performing an operation multiple times produces the identical outcome as performing it once (`f(f(x)) = f(x)`). In distributed Go systems, HTTP PUT/DELETE handlers and message queue consumers use idempotency keys to prevent duplicate billing or side effects during network retries.

### Inlining (Compiler Inlining)
An ahead-of-time compiler optimization where the body of a small function is substituted directly at the call site, eliminating the overhead of stack frame setup, argument passing, and function return instructions. View compiler inlining decisions via:
```bash
go build -gcflags="-m -m"
```

### Itable (Interface Method Table)
The internal runtime data structure (`runtime.itab`) that maps the concrete type's method set to the interface's required methods. Generated dynamically on first interface assignment and cached for subsequent instantaneous dynamic dispatch.

### I/O Multiplexing (Netpoller)
The kernel mechanism (`epoll` on Linux, `kqueue` on macOS, `IOCP` on Windows) that monitors multiple file descriptors to see if I/O operations can proceed without blocking. Go's runtime integrates this directly, allowing synchronous-looking Go code to execute non-blockingly.

### Immutable Data Pattern
A software design practice where data structures cannot be modified after creation. In Go, immutability is achieved by returning unexported struct values with accessor methods or value receivers, preventing concurrent race conditions without mutex locking.

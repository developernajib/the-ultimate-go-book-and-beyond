## N

### Named Return Values
Function signature parameters defined with explicit variable names in the return signature (e.g., `func Calculate() (result int, err error)`). Named returns are initialized to their types' zero values upon function entry and can be modified directly within the function. While useful for documentation and deferred closures, "naked returns" (omitting return arguments) are discouraged in functions longer than a few lines.

### Netpoller
The Go runtime subsystem that integrates operating system I/O multiplexing primitives (`epoll` on Linux, `kqueue` on macOS/BSD, `IOCP` on Windows) directly into the Go scheduler. When a goroutine performs network I/O, the netpoller puts the goroutine to sleep without blocking the underlying OS thread, waking the goroutine only when socket readiness is signaled.

### Nil
A predeclared identifier in Go representing the zero value for pointers, interfaces, channels, slices, maps, and function types. `nil` has no untyped identity and cannot be assigned to concrete value types like `int` or `string`.

### Nil Interface vs Interface Containing Nil
A classic Go gotcha. An interface in Go is represented internally as a two-word header: `(type_descriptor, data_pointer)`. An interface variable is `nil` if and only if both the type descriptor and the data pointer are `nil`. If a concrete pointer holding `nil` is assigned to an interface, the interface's data pointer is `nil`, but its type descriptor is non-nil, meaning `if iface != nil` evaluates to `true`!

```go
var err *MyCustomError = nil
var iface error = err
println(iface == nil) // FALSE! Type descriptor is *MyCustomError
```

### Non-Blocking I/O
System call operations that return immediately with an error (e.g. `EAGAIN` or `EWOULDBLOCK`) if the requested data is not yet available, rather than placing the calling thread in a wait state.

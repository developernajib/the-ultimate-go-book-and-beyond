## Z

### Zero-Allocation
A software engineering discipline where algorithms and hot execution paths are designed to produce zero heap allocations. Techniques include using preallocated memory arenas, reusing structs via `sync.Pool`, passing pointers to stack-allocated variables, and utilizing slice sub-slicing instead of string concatenations.

### Zero-Copy
Techniques for transferring data from network interfaces or disk storage directly to destination file descriptors without copying the payload into userspace memory buffers. In Linux and Go, zero-copy operations are achieved via system calls like `sendfile`, `splice`, and `vmsplice`, dramatically lowering CPU utilization and memory bus contention.

### Zero Value
The default value automatically assigned to any variable in Go upon declaration without an explicit initializer. Go is designed around the principle of **"Make the zero value useful"**:
- `int`, `float64`: `0`, `0.0`
- `bool`: `false`
- `string`: `""` (empty string, not nil)
- Pointers, Interfaces, Functions, Channels, Slices, Maps: `nil`
- Structs: Recursively initialized with zero values for all fields (e.g. `sync.Mutex{}` is immediately valid and ready to lock without a constructor call).

### ZigZag Encoding
An integer encoding algorithm that maps signed integers onto unsigned integers so numbers with small absolute values (like -1, 1, -2) result in small unsigned integers. Used extensively in Protocol Buffers and Gorilla time-series compression to maximize the efficiency of variable-length varint encoding.

### Zombie Process
A terminated Unix process whose execution has ended, but whose process table entry remains because the parent process has not yet read its exit status code via `wait()` or `waitpid()`. In Go container init systems, improper handling of child process signals can leak zombie processes until the container's PID limit is exhausted.

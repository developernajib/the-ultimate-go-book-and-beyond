## Future Trends

Audio DSP is a mature field with most fundamental algorithms settled decades ago. The active research and product directions in 2026 are concentrated in machine learning models for audio processing, neural codecs, personalized spatial audio, and the open question of how to run any of this on the audio thread without breaking real-time guarantees.

### ML Models for Audio Processing

Three categories of ML in production audio:

#### Noise Suppression and Voice Enhancement

**RNNoise** (Mozilla / Xiph, 2017) is a small recurrent neural network for voice noise suppression. Open source, runs in 0.1% CPU on a laptop, the model is about 85 KB. Used by OBS Studio, mumble, jitsi, and embedded in libwebrtc as an option.

**NVIDIA Broadcast** and **Krisp** are commercial extensions: larger models, more aggressive noise removal (typing, dog barks, doorbells), at the cost of running a substantially bigger network. NVIDIA Broadcast uses RTX tensor cores for inference. Krisp runs on CPU but uses a heavier model.

**Apple Voice Isolation** (iOS 15+, macOS 12+) ships an ML-based noise suppressor running on the Neural Engine. Sub-millisecond per 10 ms block on M-series chips.

Architecture pattern: take an STFT, run a small recurrent or convolutional network on the magnitude spectrum, output a per-frequency-bin gain mask, multiply, ISTFT.

#### Source Separation (Stems)

**Demucs** (Meta, 2019+, MIT-licensed), **Spleeter** (Deezer, 2019, MIT), and **MDX-Net** (Sony, 2021) extract drums, bass, vocals, and other stems from a stereo mix. Used by Logic Pro's Stem Splitter feature, FL Studio's `Slice X`, Serato's Stems, and dozens of consumer remix apps.

These models are not real-time. They run offline on the full song and output stems, which the user then loads into a session. Real-time variants exist but with reduced quality and 30+ ms latency.

#### Neural Codecs

Covered briefly in section 16. **Lyra** (Google), **Encodec** (Meta), **SoundStream** (Google) encode audio as discrete tokens generated by a small autoregressive model, decode by another small model. Bitrates as low as 3 kbps for intelligible voice. Lyra v2 ships in production in Google Meet's low-bandwidth mode.

Limitations: the decoder runs a neural network per frame on the playback path. Inference cost is non-trivial (5-10% CPU on a phone for Lyra), inference latency is variable (model dispatch through accelerator can have unpredictable jitter), and quality degrades on out-of-distribution signals (music played through a voice codec sounds bad).

#### Music Generation

**MusicGen** (Meta, 2023), **Stable Audio** (Stability AI, 2023), **Suno**, **Udio** generate music from text prompts. Quality has improved dramatically. None of these run in real time on the audio thread, they generate offline.

**Eleven Labs** for voice synthesis is a related category. Real-time TTS at conversational latency (~300 ms first audio) is achievable on the GPU but not on the audio thread.

### ML Inference and Real-Time Constraints

The fundamental tension: the audio thread needs bounded execution time, ML inference is variable. Inference involves:

- Model dispatch overhead through the framework (TFLite, Core ML, ONNX Runtime, NCNN, libtorch).
- Copying tensors to and from accelerator memory.
- Dispatch to GPU or NPU, which has its own queue.
- Variable execution time depending on cache state.

For models small enough to run synchronously on the audio thread (RNNoise, small denoisers), inference is bounded and acceptable. For larger models, inference must run off-thread with a sample-accurate handoff:

```cpp
// Audio thread: collect input, push to inference thread, pop output, mix.
class MLEffect {
    SpscRingBuffer<Block, 8> inferenceIn_;
    SpscRingBuffer<Block, 8> inferenceOut_;

public:
    void process(float* buf, int n) noexcept {
        Block in;
        std::copy(buf, buf + n, in.data);
        inferenceIn_.try_push(in);

        Block out;
        if (inferenceOut_.try_pop(out)) {
            // Use processed output, blended with dry to handle pipeline lag.
            std::copy(out.data, out.data + n, buf);
        }
        // If the inference thread is behind, fall back to dry signal.
    }
};

// Inference thread: not realtime priority, blocking model calls.
void inferenceLoop() {
    while (running) {
        Block in;
        if (inferenceIn_.try_pop(in)) {
            Block out = model.run(in);
            inferenceOut_.try_push(out);
        }
    }
}
```

Latency added: at minimum one block delay (handoff) plus inference time. Acceptable for offline-style processing within a real-time chain (denoising before encoding for a recording), unacceptable for live monitoring.

### Personalized Spatial Audio

Apple's Personalized Spatial Audio (iOS 16+, macOS 13+) uses an iPhone TrueDepth camera scan of the user's ears to pick a personalized HRTF from a proprietary collection. The improvement over generic HRTF is real but subtle. Sony's 360 RA has a similar feature using a photo of the ear.

Future direction: per-user HRTFs derived from depth scans, magnetic head tracking that actually works at gym-grade dynamic range, and integration with VR headsets that already track head orientation. Apple Vision Pro implements a portion of this for its first-party spatial audio.

### Object-Based Audio in Streaming

Atmos has now reached the consumer. Going forward, expect:

- **More tracks released in Atmos.** Apple Music's Spatial Audio catalog grows monthly.
- **Adaptive renderers.** The streaming service renders the master to whatever the client device is (headphones, soundbar, surround, single speaker).
- **Real-time game integration.** Xbox Wireless Controller with Dolby Atmos is one example, live-mixed Atmos for game audio is the natural extension.

The senior audio engineer building products in 2026 should design with object-based audio as a first-class output format, not an afterthought.

### In-Ear Active Processing

AirPods Pro 2 and competitors run active noise cancellation, transparency mode, conversation boost, and Adaptive Audio (a hybrid of NC and transparency that adjusts based on the environment). All of this runs on the H2 chip in the AirPod itself, in C and C++ for the DSP, with model-based components for the speech detection and wind reduction.

The engineering challenge for in-ear devices is fitting useful processing into a battery-powered chip with ~5 mW of audio DSP budget. Models are small (sub-100 kB) and fixed-point. Latencies are sub-millisecond because human voice perception is very sensitive to local ear-occlusion delay.

### Cross-Plugin Standards

CLAP gained ground in 2024-2025. As of 2026 it is a real third option after VST3 and AU. The trajectory suggests CLAP will continue to grow because it is open, modern, and aligned with the most active DAW developers (Bitwig, Reaper, Studio One, FL Studio).

VST2 is gone for new releases. Steinberg licensed it openly under a community-friendly arrangement after years of pressure but new plugins target VST3 + AU + CLAP plus AAX for Pro Tools.

### Scripting Languages on the Audio Thread

Faust (Grame), Cmajor (Sound Stacks), and SOUL (formerly the JUCE team's effort, since superseded by Cmajor) are domain-specific languages that compile to C++ or LLVM and let DSP authors write algorithms in a high-level form. Faust has 20 years of academic momentum. Cmajor is the modern entry, designed for plugin development with full real-time guarantees.

The senior plugin developer in 2026 is increasingly likely to use a DSL for the math and C++ for the integration, rather than writing every filter and oscillator by hand.

### Where to Bet

If you are picking what to learn deeply for the next five years:

1. **Spatial audio / Atmos / personalized HRTF.** Adoption is growing fast and most teams are short on engineers who can both DSP and C++ real-time.
2. **Neural denoising and voice enhancement on-device.** Apple, Microsoft, Google all have teams here, and the market is forming around lower-end devices.
3. **CLAP plugin format.** Smaller but growing. Knowing CLAP gives you optionality.
4. **Cmajor or Faust.** A productivity multiplier for DSP authoring.
5. **Real-time ML inference frameworks (Core ML, TFLite Micro, NCNN).** Where the next class of audio products will live.

The fundamentals (biquads, FFT, real-time discipline) are not going anywhere. Build on them. The ML and spatial layers are where the differentiation in shipping products will come from.

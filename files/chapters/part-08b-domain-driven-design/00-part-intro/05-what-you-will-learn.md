## What You Will Learn

By the end of this part, you will be able to:

- Explain DDD strategic concepts (Bounded Contexts, Context Maps, Ubiquitous Language) in a system design interview and in a real team setting
- Identify the correct boundaries for bounded contexts in a real system
- Implement Entities, Value Objects, Aggregates, and Domain Events in idiomatic Go
- Structure a Go project using DDD layered architecture
- Apply the Repository pattern to abstract data access behind domain interfaces
- Build a complete DDD application with domain, application, and infrastructure layers in Go
- Implement CQRS with command and query buses in Go
- Implement Event Sourcing with a PostgreSQL event store in Go
- Test domain logic without infrastructure dependencies
- Understand the trade-offs of CQRS and Event Sourcing and know when to use them
- Discuss DDD, CQRS, and Event Sourcing trade-offs at a Staff or Principal Engineer level

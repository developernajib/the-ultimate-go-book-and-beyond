## Exercises

1. **Tamper-Evident Audit Log Verification (SOC 2 CC7.2)**: Build a Go utility that verifies an audit log stream protected by HMAC chaining. The program must accept an audit log file, recalculate the HMAC of each record concatenated with the previous record's hash, and detect any modified payload, deleted record, or out-of-order insertion. Provide a test suite demonstrating that altering a single byte in an older log record immediately invalidates all subsequent verification hashes.

2. **GDPR Right-to-Erasure Pipeline with Cryptographic Shredding (Article 17)**: Implement an asynchronous deletion pipeline in Go. When a data subject submits an erasure request, the service must cryptographically shred the user's dedicated encryption key (rendering all ciphertext irrevocably unreadable) and replace identifiable database rows with anonymized placeholders (`[ERASED]`). Ensure the pipeline respects retention exceptions (e.g., retaining financial ledger entries for 7 years as required by tax law while deleting marketing profiles).

3. **PCI DSS Boundary Tokenizer (Requirement 3.5.1)**: Create a boundary reverse-proxy middleware that intercepts credit card payloads before they reach application microservices. The middleware must validate the 16-digit PAN against the Luhn algorithm, generate an opaque UUID token associated with the cardholder data in an encrypted token vault, and substitute the token into the request body so downstream handlers never see or store raw card numbers.

4. **HIPAA Minimum-Necessary Access Middleware & Safe Harbor Redactor**: Implement a Go HTTP middleware for healthcare endpoints that inspects the caller's clinical role (e.g., `doctor`, `nurse`, `billing_clerk`) and filters patient JSON records to expose only the minimum necessary attributes. Attach a pipeline redactor that strips the 18 HIPAA Safe Harbor direct identifiers (Social Security Numbers, medical record numbers, full names, dates of birth) from error logs and debugging traces.

5. **Automated SOC 2 Evidence Collection Daemon**: Write a background Go daemon that periodically validates security controls across your service environment (e.g., verifying that all TLS listeners require TLS 1.3, checking that database storage is encrypted, and verifying database connection pools use mutual TLS). The daemon must export evidence as cryptographically signed JSON artifacts with SHA-256 digests and expose Prometheus metrics reflecting current control compliance status.

6. **Data Residency Enforcement Layer (GDPR Chapter V)**: Build a residency-aware storage dispatcher in Go that evaluates data classifications (`CategoryPersonal`, `CategoryPHI`, `CategoryFinancial`) and target geographic regions (`RegionEU`, `RegionUS`, `RegionAPAC`). The dispatcher must fail closed on any attempt to write EU personal data to a non-EEA storage backend unless a configured `TransferMechanism` (such as Standard Contractual Clauses or an Article 45 adequacy decision) is explicitly attached to the context.

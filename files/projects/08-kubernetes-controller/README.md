# Project 08: Kubernetes PostgreSQL Operator

A Kubernetes operator (controller) that manages PostgreSQL clusters as first-class Kubernetes resources. Declare a `PostgresCluster` custom resource and the operator provisions StatefulSets, Services, ConfigMaps, Secrets, PersistentVolumeClaims, and optional backup CronJobs - then continuously reconciles to keep the cluster in the desired state.

## Architecture Overview

```
kubectl apply -f cluster.yaml
         |
  [Kubernetes API Server]
         |
  [PostgresCluster CRD]  ← admission webhook validates spec
         |
  [Controller Reconciler]
         |
   ┌─────┴──────────────────────────┐
   │  StatefulSet  Service  ConfigMap│
   │  Secret  PVC  CronJob (backup) │
   └────────────────────────────────┘
         |
  [Prometheus metrics endpoint :8080]
  [Health probes              :8081]
  [Webhook server             :9443]
```

**Key packages:**
- `api/v1alpha1/postgrescluster_types.go` - CRD type definitions with kubebuilder markers
- `api/v1alpha1/zz_generated.deepcopy.go` - generated DeepCopy methods (do not edit)
- `api/v1alpha1/postgrescluster_webhook.go` - admission webhook: defaulting + validation
- `internal/controller/postgrescluster_controller.go` - reconciliation loop
- `internal/metrics/metrics.go` - Prometheus metrics for operator health

## Step-by-Step Build Guide

### Step 1 - Understand the CRD Types

**File:** `api/v1alpha1/postgrescluster_types.go`

`PostgresCluster` is the custom resource. Its `Spec` fields are:

| Field | Type | Description |
|-------|------|-------------|
| `version` | string | PostgreSQL version, e.g. `"16.1"` |
| `replicas` | int32 | Number of instances (1-10) |
| `storage.size` | string | PVC size, e.g. `"10Gi"` |
| `resources` | ResourceRequirements | CPU and memory requests/limits |
| `image` | string | Container image override |
| `parameters` | map[string]string | `postgresql.conf` key-value pairs |
| `backup` | BackupSpec | Optional: S3-based backup with cron schedule |
| `ha` | HASpec | Optional: sync/async replication mode |
| `monitoring` | MonitoringSpec | Optional: postgres-exporter sidecar |

`Status` fields updated by the reconciler:
- `phase` - `Pending | Creating | Running | Failed | Deleting`
- `conditions` - Kubernetes standard conditions (`Ready`, `StatefulSetReady`, etc.)
- `replicas` / `readyReplicas`
- `primaryInstance`

**What to test:** Confirm that `IsReady()` returns false when the `Ready` condition is absent. Confirm `SetCondition` updates the message without resetting `LastTransitionTime` when the status has not changed.

### Step 2 - Understand the Generated DeepCopy

**File:** `api/v1alpha1/zz_generated.deepcopy.go`

This file is generated by `controller-gen` and must not be edited by hand. It implements `runtime.Object` for the types so they can be stored in the Kubernetes API.

Regenerate after any type change:
```bash
make generate
```

**What to test:** Verify `go build ./...` passes after regeneration. The generated file must compile with the current type definitions.

### Step 3 - Understand the Admission Webhook

**File:** `api/v1alpha1/postgrescluster_webhook.go`

Two webhook operations:
- **Defaulting** (`Default()`) - fills in defaults (image tag, replica count, storage access mode) so the user does not need to specify every field
- **Validation** (`ValidateCreate()`, `ValidateUpdate()`, `ValidateDelete()`) - enforces business rules (e.g., storage size cannot be decreased on update, version string must match the pattern `^\\d+\\.\\d+`)

The webhook is served by controller-runtime on port 9443. A TLS certificate must be present at the path specified in `WebhookServer.CertDir` (defaults to `/tmp/k8s-webhook-server/serving-certs`).

**What to test:** Instantiate a `PostgresCluster` with no image set, call `Default()`, and assert the image is now set. Call `ValidateCreate()` with an empty `storage.size` and assert an error is returned.

### Step 4 - Understand the Controller Reconciliation Loop

**File:** `internal/controller/postgrescluster_controller.go`

The `Reconcile` function is called whenever a `PostgresCluster` resource changes. The loop:

1. Fetch the `PostgresCluster` object (return if not found - it was deleted)
2. Add a finalizer on first reconcile to handle cleanup
3. If the object is being deleted, run cleanup (delete StatefulSet, Services, etc.) and remove the finalizer
4. Set phase to `Creating` if no StatefulSet exists yet
5. Create or update the **ConfigMap** (postgresql.conf content)
6. Create or update the **Secret** (postgres superuser password)
7. Create or update the **StatefulSet** (one pod per replica)
8. Create or update the **headless Service** (for StatefulSet DNS)
9. Create or update the **read/write Service** (load balanced)
10. If backup is enabled, create or update the **CronJob**
11. Observe StatefulSet status and update `PostgresCluster.Status`
12. Requeue based on phase: 10s when creating, 5m when running

Requeue intervals are defined as constants:
```go
requeueAfterError    = 30 * time.Second
requeueAfterNormal   = 5 * time.Minute
requeueAfterCreating = 10 * time.Second
```

**What to test:** Use `envtest` (controller-runtime's in-process API server) to create a `PostgresCluster` and assert the StatefulSet and Services are created. Assert the status phase transitions from `Pending` to `Running` once the StatefulSet reports ready replicas.

### Step 5 - Understand the Metrics

**File:** `internal/metrics/metrics.go`

Prometheus metrics exposed by the operator:
- `postgres_operator_reconcile_total` - counter of reconcile calls (labels: `result=success|error`)
- `postgres_operator_reconcile_duration_seconds` - histogram of reconcile duration
- `postgres_operator_clusters_total` - gauge of managed clusters by phase

These are served on `:8080/metrics` by the controller-runtime metrics server.

**What to test:** Call the reconcile function in a test and assert the counter increments.

### Step 6 - Understand Leader Election

**File:** `cmd/main/main.go`

The manager is started with `--leader-elect` flag support. When enabled, only one instance of the operator is active at a time, using a Kubernetes Lease object as a distributed lock. This prevents split-brain when running multiple replicas for high availability.

Key flags:
```
--leader-elect                          (default: false)
--leader-election-id                    postgres-operator-leader
--leader-election-namespace             default
--leader-election-lease-duration        15s
--leader-election-renew-deadline        10s
--leader-election-retry-period          2s
```

**What to test:** Start two manager instances in tests - assert only one becomes the leader. Kill the leader and assert the second instance takes over within `leaseDuration`.

### Step 7 - Wire Everything in main.go

**File:** `cmd/main/main.go`

`main.go` registers both the `PostgresCluster` scheme and the core Kubernetes scheme, creates the controller-runtime manager, registers the reconciler, registers the webhook, adds health and readiness probes, then starts the manager with signal handling.

**What to test:** Run `go build ./...` with no errors. Run `make run` against a live cluster (or `make run-envtest`) and apply the sample manifest.

## Running the Project

### 1. Start a local Kubernetes cluster

```bash
# Using minikube
minikube start

# OR using kind
kind create cluster --name postgres-operator
```

### 2. Install the CRD

```bash
make install
```

This runs `controller-gen` to generate the CRD YAML and applies it with `kubectl apply`.

### 3. Run the operator locally (out-of-cluster)

```bash
make run
```

The operator connects to the cluster via `~/.kube/config`.

### 4. Apply a sample PostgresCluster

```bash
kubectl apply -f config/samples/postgrescluster.yaml
kubectl get postgresclusters
kubectl describe postgrescluster my-cluster
```

### 5. Run tests

```bash
make test
```

### 6. Build and push the operator image

```bash
make docker-build IMG=your-registry/postgres-operator:latest
make docker-push  IMG=your-registry/postgres-operator:latest
```

### 7. Deploy to cluster

```bash
make deploy IMG=your-registry/postgres-operator:latest
```

## API - Custom Resource

### PostgresCluster

```yaml
apiVersion: database.example.com/v1alpha1
kind: PostgresCluster
metadata:
  name: my-cluster
  namespace: default
spec:
  version: "16.1"
  replicas: 3
  storage:
    size: 10Gi
    storageClassName: standard
  resources:
    requests:
      cpu: "500m"
      memory: "1Gi"
    limits:
      cpu: "2"
      memory: "4Gi"
  parameters:
    max_connections: "200"
    shared_buffers: "256MB"
  backup:
    enabled: true
    schedule: "0 2 * * *"
    retention: 7
    s3:
      bucket: my-pg-backups
      region: us-east-1
      credentialsSecret: s3-credentials
  ha:
    enabled: true
    syncReplicas: 1
    replicationMode: sync
  monitoring:
    enabled: true
```
